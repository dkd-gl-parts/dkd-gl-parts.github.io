# 管理者限定のバックアップ用パスワード登録券

状態: `v1.1.1064` 候補。ローカル検証済み、未公開。

## 操作

コンシェルジュ設定の管理者用Windows連携欄で、本人の承認済み端末の公開鍵
ファイルを選択し、PCの専用登録ツールを先に開く。登録券を発行・コピーし、
60秒以内にPCのツールへ貼り付けて、本人が非表示入力でパスワードと確認を入力する。
ブラウザにはパスワード欄を設けず、APIへ渡す本文は端末IDだけ。

登録券はブラウザのメモリと読取専用欄にだけ保持し、期限切れ、画面を閉じる、
ファイルや利用者の変更で消去する。処理中と有効な券の保持中は重複発行を止める。
古い要求が画面を閉じた後に完了しても券を再表示しない。コピーは本人のボタン操作で行う。
コピー済みのクリップボードは他の作業を上書きしないが、券は最大60秒で失効する。

権限はサーバーで検証する。認証失効、権限不足、未承認端末、受付停止は券を表示せず案内する。
端末承認は既存の一回限りの監査付き操作を使う。登録券の発行だけで販売王への
ログインやデータ取込を利用可能とは表示しない。

## 配備条件

- 対応するサーバー修正、専用の認証セッション付き読取RPC、署名鍵、PC側公開検証鍵と
  登録ツールが必要。サーバーの受付フラグは既定OFFで、登録時にのみ一時的に開く。
- 追加RPC権限と鍵/端末導入はプロジェクト規則に従い対象を特定して確認する。
- パスワード入力と送信は本人に引き継ぐ。実パスワードや実登録券をテストに使わない。

## 検証

- 既存workflow由来のNode 111検査、静的ビルド、セキュリティヘッダー検査が成功。
- API境界: 非管理者、別利用者、余分なパスワード/セッション指定、無効な端末IDを拒否。
- runtime: 重複発行防止、コピー、期限切れ、保持しないこと、画面を閉じた後の遅い応答、
  401/403/409/503の券非表示を合成データで確認。
- Chromeの合成ページで1200×800と390×844の登録欄/券表示を視認。受付停止時に
  券が表示されず、staffのページに管理者操作が存在しないことを確認。
- 画面試験のタブを閉じ、viewportをreset。既存ユーザータブは保持。

## 戻し方

受付フラグを閉じた状態を維持し、必要なら直前main `ad73c81` の配信へ戻す別レビューを行う。
配信の切戻しだけではPCの登録済みパスワードや鍵を消去しない。実際の切戻しは別承認。
