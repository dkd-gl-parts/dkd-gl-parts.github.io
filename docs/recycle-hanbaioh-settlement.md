# Recycle+ 販売王の専用連携（実装候補）

本番未公開・販売王実機未受入。受注詳細の「販売王へ売上・入金を連携」から使用する候補です。専用連携は初期状態で無効です。

1. 管理者が販売王にブロードリーフ得意先を登録し、実際のコードと確認根拠を設定します。D-CATSの社内コードBROADLEAFをそのまま使いません。
2. 出荷と決済確認を完了し、見込10%とは別に精算明細の実手数料を確定します。
3. 実際の差引着金日・金額・明細根拠を入力し、売上総額＝手数料＋差引着金であることを確認して連携データを固定します。以後、この元伝票の決済/手数料/売上日は変更できません。
4. 売上56列の同じCSVを保存し、取込直前backup・伝票番号重複なし・税設定・0件エラーを販売王で確認します。取込着手を記録し、1回だけ取り込みます。応答が不明な場合は再取込しません。
5. 販売王から対象伝票を独立に出力します。実際の出力形式が標準55列か特例対応56列かを選び、見出しなしのCSVと確認根拠で照合します。入力専用の特例対応は標準55列では読戻せないことを記録します。
6. 売上の照合後、入金13列を取得します。振込は差引実入金、その他は明示したファクタリング手数料控除です。取込前確認後に1回だけ取り込み、独立に出力した入金CSVを照合します。
7. 両伝票の日付以降の販売王得意先元帳で売掛残高0円を確認し、基準日・表示残高・根拠を記録します。これは担当者による確認記録です。請求締切/伝票別の消込済み状態を自動確認した意味ではありません。

売上額を手数料分だけ減らしたり、差引額だけを売上にしたりしません。入金伝票には手数料の消費税欄がないため、控除額/任意の内税/精算根拠はD-CATSで保持します。「その他」から会計製品へ連携する場合は、費用・税の対応を別途確認します。既存のその他区分全体の勘定設定を勝手に変更しません。

料率などの条件変更は受注時snapshotを保持します。連携後の差額・返金・取消は、既存伝票を消して再出力する方法では処理しません。訂正伝票は別機能です。

保存済み資格による自動ログインと同一sessionでのbackup/取込/読戻しは継続要件です。本画面だけでPC側の入金adapterが完成したとは扱いません。
