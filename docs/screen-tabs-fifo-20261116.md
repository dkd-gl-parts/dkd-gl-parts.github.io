# 開いた順に残す画面タブ（v1.1.1334）

山本限定pilot・初期OFF。通常のメニュー画面から開いた順にタブを追加し、最大9個を保持する。タブ専用の固定メニュー一覧は使わず、通常メニューの定義と閲覧条件を共用する。

- 同じ画面は既存タブへ切り替え、開いた順番を変えない。
- 10個目では一番古いタブを閉じて右端へ追加する（FIFO）。
- 未保存の可能性がある入力変更は閉じる前に確認。キャンセルすると新しい画面を開かず、9個と順番、入力を保持する。
- ×で閉じる時と、タブをOFFにする時も同じ確認を行う。
- 保存処理中/保存結果が未確認のワークスペースは閉じず、確認が終わるまで待つ。
- 保存成功を確定できない入力変更も安全側で確認対象にする。入力を元に戻すと確認不要。入力値・パスワードはタブ用保存領域に書かず、画面内メモリだけで判定する。
- メニューの挨拶下「画面タブ（試験）」でON/OFF。元の←メニューを使用、タブ列35pxを維持。
- 設定/撮影/印刷等のダイアログや画面内の詳細は、その画面内で扱う。ダイアログ専用の新しいタブは作らない。
- 再読込は9個のメニュー画面と開いた順番、選択タブを復元。業務の未保存入力そのものは再読込で復元しない。入力変更が残る時は自動更新を待ち、手動再読込にはブラウザ確認を出す。
- 閲覧権限・本来の業務API/RLSを維持し、非pilotにタブを表示しない。全員公開は未承認。

既存CIとこのPCのheadlessで確認し、本番反映は本人の事前承認後に行う。戻す時はこの変更だけをrevertする。直前main36053d9/v1.1.1330を参照し、他タスクの変更をまとめて戻さない。

本番確認で、画面幅を狭めた直後に選択タブが見切れる場合を検出。v1.1.1334候補では幅変更時にタブ列の横スクロールだけを調整し、タブ順・入力・キーボードフォーカスを保持する。35pxを維持する。

タブON時もヘッダーを装飾線の位置基準にする。ヘッダーを通常フロー内のrelative配置とし、赤い装飾線がメニュー上へ浮かないようにする。警告表示の追加ではない。

狭い画面ではヘッダー左側のロゴ・端末表示・版/更新を折り返し、320pxでも横にはみ出さないようにする。タブ列の35pxは変更しない。
